# Lote P3 — Habitaciones `1–9` Editables sin Colisión `Room.id` vs `Room.number`

## 1. Qué hace
- Elimina en [web_operations.py](../../apps/api/routers/web_operations.py) la resolución ambigua `or_(Room.number == ref, Room.id == int(ref))`: ahora `PUT/PATCH/DELETE /api/v1/rooms/{room_id}` y `POST /api/v1/bookings/manual` resuelven estrictamente por clave primaria `Room.id`.
- Agrega `POST /api/v1/rooms` (HTTP `201`) y habilita la edición del campo `number` en `PUT /api/v1/rooms/{room_id}` con validación de unicidad y captura de `IntegrityError` devolviendo HTTP `409 Conflict` si el número ya pertenece a otra habitación.
- Corrige el ordenamiento en [room_service.py](../../apps/api/services/room_service.py) y [web_operations.py](../../apps/api/routers/web_operations.py) usando `func.length(Room.number), Room.number.asc()` para que `1..9, 10` conserve orden numérico real.
- Desbloquea el campo **Número de habitación** al editar en [Rooms.tsx](../../apps/web/src/screens/Rooms.tsx) y ajusta `updateRoom`/`deleteRoom`/`setRoomStatus` en [store.tsx](../../apps/web/src/store.tsx) para comparar por `id` sin colisionar con `number`.

## 2. Por qué así
- Cuando las habitaciones pasan de `101..303` a `1..9`, un parámetro `room_ref = "2"` es numérico y coincide tanto con `id=2` como con un eventual `number="2"`. Buscar con `OR` podía editar o cancelar la habitación equivocada.
- Al depender únicamente de `Room.id` en las rutas de recurso (`/rooms/{room_id}`) y en `booking.room_id`, cambiar el número visible de un cuarto no rompe reservas históricas ni estadísticas.

```bash
cd apps/web && npm run build
```

## 4. Tres preguntas de defensa
1. **¿Por qué `or_(Room.number == ref, Room.id == int(ref))` es peligroso al usar números `1–9`?**
   > Porque si la habitación con `id=1` cambia su número a `"2"`, una petición a `PUT /api/rooms/2` haría match con dos filas y `.first()` podría modificar `id=1` en lugar de `id=2`.
2. **¿Cómo evitan que `"10"` aparezca entre `"1"` y `"2"` al listar habitaciones?**
   > Ordenando primero por `func.length(Room.number)` y luego lexicográficamente por `Room.number.asc()`, de modo que números de 1 dígito preceden a los de 2 dígitos.
3. **¿Qué respuesta recibe el Administrador si intenta asignar un número de habitación ya ocupado?**
   > HTTP `409 Conflict` tanto por verificación previa (`Room.number == new_num, Room.id != room.id`) como por captura defensiva de `IntegrityError` ante condiciones de carrera.
