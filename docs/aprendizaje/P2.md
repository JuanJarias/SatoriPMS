# Lote P2 — RBAC Estricto con JWT y Clave Interna `X-Service-Key` en Todos los Routers

## 1. Qué hace
- Extiende [apps/api/dependencies/auth.py](../../apps/api/dependencies/auth.py) con:
  - `require_service_key`: valida en tiempo constante (`hmac.compare_digest`) la cabecera `X-Service-Key` contra `N8N_INTERNAL_API_KEY`.
  - `require_service_or_role`: autoriza peticiones mediante `X-Service-Key` (flujo n8n) o JWT Bearer con rol autorizado (`Administrador` / `Recepcionista`), devolviendo HTTP `401` o `403` según corresponda.
  - `resolve_actor_name`: registra el `username` real en `audit_log` en vez de strings fijos (`recepcion`, `admin_web`).
- Protege todos los endpoints operativos en [rooms.py](../../apps/api/routers/rooms.py), [bookings.py](../../apps/api/routers/bookings.py), [conversations.py](../../apps/api/routers/conversations.py), [n8n_compat.py](../../apps/api/routers/n8n_compat.py) y [web_operations.py](../../apps/api/routers/web_operations.py).
- Elimina los endpoints abiertos `POST /api/bookings/test-paid` y `GET /api/bookings/debug`, reemplazándolos por `POST /api/v1/bookings/manual` y `GET /api/v1/bookings` protegidos por JWT.
- Agrega `PATCH /api/v1/rooms/{room_ref}/status` para que Recepción cambie el estado físico de limpieza/mantenimiento sin acceder a edición de tarifas/eliminación (`Administrador`).

## 2. Por qué así
- Dejar `web_operations.py`, `n8n_compat.py` y `conversations.py` abiertos permitía que cualquier petición anónima consultara datos personales (violación a Ley 1581) o alterara precios/reservas.
- n8n necesita operar sesiones, disponibilidad, candados y cancelaciones sin simular credenciales humanas de usuario; `X-Service-Key` autentica máquina a máquina en tiempo constante (`hmac.compare_digest`).

## 3. Cómo probarlo
```bash
.venv/bin/pytest tests/test_auth.py tests/test_n8n_integration.py tests/test_web_operations.py -v
cd apps/web && npm run build
```

## 4. Tres preguntas de defensa
1. **¿Por qué validar `X-Service-Key` con `hmac.compare_digest` en vez de `==`?**
   > `hmac.compare_digest` compara en tiempo constante y mitiga ataques de canal lateral (*timing attacks*) que podrían inferir bytes de la clave interna midiendo latencias.
2. **¿Por qué Recepción tiene `PATCH /rooms/{id}/status` separado de `PUT /rooms/{id}`?**
   > Principio de mínimo privilegio (RBAC RN-10): Recepción debe poder marcar una habitación en `cleaning` o `maintenance` durante la jornada, pero solo `Administrador` puede cambiar tarifas (`price_per_night`) o retirar cuartos del inventario.
3. **¿Qué ocurre si alguien llama a `/api/bookings/test-paid` o `/api/bookings/debug`?**
   > Ambos endpoints demo abiertos fueron eliminados (retornan HTTP `404`), sustituidos por `POST /api/v1/bookings/manual` y `GET /api/v1/bookings` bajo JWT obligatorio (`401` si falta).
