# Aprendizaje P9 — Docker de Producción, Proxy Nginx, Sentry y Respaldo Cifrado R2

**POR QUÉ**  
En desarrollo Vite (`:5173`) sirve el frontend por separado de FastAPI (`:8080`), el contenedor `api` corría como `root` sin `HEALTHCHECK`, no existía observabilidad de excepciones ni automatización de respaldos cifrados fuera del servidor, y `docs/Guia_Configuracion_Entorno.md` seguía mencionando Redis para `V9`.

**QUÉ SE HIZO**  
1. **Endurecimiento de API ([apps/api/Dockerfile](../../apps/api/Dockerfile), [apps/api/requirements.txt](../../apps/api/requirements.txt), [apps/api/main.py](../../apps/api/main.py)):** usuario sin privilegios `satori`, `HEALTHCHECK` contra `/api/v1/health` e inicialización condicional de `sentry-sdk[fastapi]` cuando `SENTRY_DSN` está definido (`send_default_pii=False` por Ley 1581).
2. **Frontend de producción y Nginx mismo origen ([apps/web/Dockerfile](../../apps/web/Dockerfile), [infra/nginx/default.conf](../../infra/nginx/default.conf), [docker-compose.prod.yml](../../docker-compose.prod.yml)):** build multi-etapa con `node:20-alpine` servido por `nginx:1.27-alpine`, enrutando `/` al SPA React y `/api/` a `api:8080` con `proxy_buffering off` para no bloquear SSE (`/api/v1/events/stream`). En `docker-compose.prod.yml` se fija `ENVIRONMENT=production`, por lo que `/api/bookings/debug` responde `404`.
3. **Respaldo diario cifrado ([scripts/backup_pg_r2.sh](../../scripts/backup_pg_r2.sh)):** ejecuta `pg_dump -Fc`, cifra localmente con `openssl enc -aes-256-cbc -pbkdf2` y sube el archivo `.dump.enc` a Cloudflare R2; soporta `--dry-run` para validar herramientas sin credenciales vivas.
4. **Configuración y documentación ([.env.example](../../.env.example), [docs/Guia_Configuracion_Entorno.md](../Guia_Configuracion_Entorno.md)):** eliminadas las referencias residuales a Redis, añadidas variables de entorno de producción/observabilidad/R2 y retirada copia duplicada de presentación en `docs/Presentaciones/`.

**CÓMO PROBARLO**  
```bash
docker compose -f docker-compose.yml config --quiet
docker compose -f docker-compose.prod.yml config --quiet
./scripts/backup_pg_r2.sh --dry-run
.venv/bin/pytest -v
(cd apps/web && npm run build && npm run test:e2e)
```

**PREGUNTAS DE DEFENSA (CON RESPUESTA)**  
1. **¿Por qué Nginx configura `proxy_buffering off` y `proxy_read_timeout 3600s` solo en `location /api/`?**  
   Para que las notificaciones en tiempo real SSE (`/api/v1/events/stream`) fluyan de inmediato hacia el navegador sin quedar retenidas en el búfer ni cortarse al minuto por inactividad.
2. **¿Cómo cumple `sentry-sdk` con la Ley 1581 de datos personales?**  
   Configurando `send_default_pii=False` en `sentry_sdk.init(...)`, evitando adjuntar cabeceras con JWT, teléfonos o cédulas en trazas de error.
3. **¿Cómo protege `docker-compose.prod.yml` la base PostgreSQL y los endpoints de prueba?**  
   PostgreSQL no publica el puerto `5432` hacia Internet (solo vive en la red interna de Docker) y `api` arranca con `ENVIRONMENT=production` y usuario Linux no-root `satori`.
