# Lote P0 — Aislamiento DB de Pruebas (`satoripms_test`) y Variables `.env`

## 1. Qué hace
- Crea [tests/conftest.py](../../tests/conftest.py) para redirigir automáticamente `DATABASE_URL` hacia una base de datos terminada en `_test` (`satoripms_test`) antes de importar los módulos de FastAPI, crearla en PostgreSQL 16 si aún no existe y aplicar `alembic upgrade head`.
- Declara en [apps/api/core/config.py](../../apps/api/core/config.py) y [.env.example](../../.env.example) las variables definitivas de **Wompi** (`PAYMENT_PROVIDER`, `WOMPI_ENVIRONMENT`, `WOMPI_PUBLIC_KEY`, `WOMPI_PRIVATE_KEY`, `WOMPI_EVENTS_SECRET`, `WOMPI_INTEGRITY_SECRET`), seguridad interna **n8n ↔ FastAPI** (`N8N_INTERNAL_API_KEY`, `N8N_EXPIRED_WEBHOOK_URL`), **Google Places** (`GOOGLE_PLACES_API_KEY`, `GOOGLE_PLACE_ID`, `GOOGLE_REVIEWS_URL`) y **Sentry** (`SENTRY_DSN`), retirando los placeholders heredados de MercadoPago.

## 2. Por qué así
- Antes de este paso, todas las suites en `tests/` importaban `AsyncSessionLocal` apuntando al mismo `satoripms` del entorno local y ejecutaban `delete(Booking)` sobre habitaciones reales, con riesgo de destruir reservas operativas al correr `pytest`.
- Inyectar `DATABASE_URL` dentro de `pytest_configure` garantiza que `Settings` (Pydantic Settings, donde el entorno del proceso tiene precedencia sobre `.env`) y el `engine` de SQLAlchemy nazcan apuntando a `satoripms_test` desde el arranque de la colección de pruebas, sin modificar los 8 archivos de test existentes y con una guarda explícita que aborta si la base no termina en `_test`.

## 3. Cómo probarlo
```bash
.venv/bin/pytest -v
cd apps/web && npm run build
```
Además se verifica que la base operativa `satoripms` conserve intactos sus registros tras ejecutar `pytest`, mientras `satoripms_test` recibe las migraciones Alembic y los datos de prueba.

## 4. Tres preguntas de defensa
1. **¿Por qué `pytest_configure` sobrescribe `os.environ["DATABASE_URL"]` en lugar de cambiar la conexión dentro de cada test?**
   > Porque `apps/api/core/database.py` instancia `engine` y `AsyncSessionLocal` a nivel de módulo al importarse. `pytest_configure` corre antes de importar `test_*.py`, logrando aislamiento global con cero duplicación.
2. **¿Qué evita que un error de configuración termine borrando la base productiva `satoripms`?**
   > `_ensure_test_database_and_schema` exige que el nombre de base de datos termine en `_test`; de lo contrario lanza `RuntimeError` antes de abrir conexiones de escritura.
3. **¿Por qué coexistir `PAYMENT_PROVIDER=sandbox` junto a las llaves `WOMPI_*` en `Settings`?**
   > Para respetar el patrón de puerto/adaptador: en desarrollo local y pruebas automatizadas el sistema corre en sandbox determinista sin depender de red externa, y en producción conmuta al adaptador Wompi con HMAC/integridad.
